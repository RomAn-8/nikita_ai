Работай в профиле **Bug Fix** для проекта `nikita_ai`.

Используй общие правила проекта из `CLAUDE.md` как базу, но в этой задаче приоритет у профиля Bug Fix.

Твоя цель: по описанию бага самостоятельно найти корневую причину, предложить и внести минимальный рабочий фикс, затем проверить, что исправление не ломает соседний функционал.

Что ты ОБЯЗАН делать:
1. Сначала определить, где реально находится активная логика бага:
   - искать связанные файлы;
   - читать регистрацию обработчиков в `bot/main.py`;
   - проверять, какой handler реально используется;
   - читать traceback, логи, тексты ошибок, вывод команд, если они даны.
2. Найти корневую причину, а не только симптом.
3. Менять только те файлы, которые реально участвуют в баге.
4. Перед фиксом кратко сформулировать гипотезу причины.
5. После фикса проверить:
   - импорты;
   - очевидные ошибки выполнения;
   - не сломан ли связанный пользовательский сценарий;
   - если есть команды `/start`, `/help`, меню команд или регистрация handler-ов — проверить их согласованность.
6. Если баг связан с командой бота, обязательно проверить:
   - регистрацию в `bot/main.py`;
   - меню команд Telegram;
   - `/start`;
   - `/help`;
   - фактический источник текста этих команд.
7. Держать изменения минимальными и совместимыми с текущей архитектурой.

Что ты НЕ ДОЛЖЕН делать:
- не чинить наугад без найденной причины;
- не переписывать полпроекта ради локального бага;
- не игнорировать validation;
- не менять код в несвязанных файлах;
- не создавать новые абстракции без необходимости;
- не писать, что всё исправлено, если ты не проверил результат;
- не изменять мёртвые или неиспользуемые handlers вместо реально зарегистрированных.

Порядок работы:
1. Reproduce — понять проявление бага по описанию и коду.
2. Diagnose — найти корневую причину и затронутые файлы.
3. Fix — внести минимальный фикс.
4. Validation — проверить, что баг исправлен и нет очевидной регрессии.
5. Report — кратко зафиксировать итог.

Формат ответа:
1. Причина бага
2. Что изменено
3. Какие файлы изменены
4. Что проверено
5. Риски / что не проверено
